## Authoritative values and invariant

Each accepted immutable entry and its sequence are committed together by `backend/src/gateway.mjs`. A close transaction captures `(tenant, year, sequence, closingVersion)` and the closed-period boundary. The isolated `archive-projection.mjs` reconstructs that checkpoint from the complete manager feed, or from a fully verified manager snapshot seed followed by contiguous changes after its checkpoint. Employee snapshots and arbitrary caller-provided compact rows cannot authorize an archive seed. Projection controls use BigInt; `archive-accounting.mjs` independently calculates controls from the restored annual records. Hand-calculated expected values below supplement source-versus-restore comparisons.

For each role/account at checkpoint C:

`closing(C) = original directory baseline + accepted effects before start + accepted effects in [start,end) through C`

The annual package expresses this as `opening(C) + period(C) = closing(C)`. A later package carries the earlier closing once, then adds only later accepted effects. The active snapshot has a different contract: it contains the **full retained accepted ledger projection at C**, including original directory baselines and dependency facts. Installation merges those immutable facts into the scoped local store and sets cursor C in one SQLite transaction. It does not import an annual opening control or create a compacted financial baseline posting. Feed deltas after C then extend the same ledger exactly once; ordinary page facts and their cursor also commit together.

`merchant` receivables and `supplier` payables remain separate signed accounts. Archived controls and statement assembly retain explicit roles, including mixed-role test fixtures. The active directory still assigns one role to each party ID; an owner needing both relationships must use the existing role-specific directory identities. No new multi-role accounting product was introduced.

## Exact representation

Money is integer piastres, quantity integer thousandths, and price integer minor units. Backend boundaries reject unsafe/noninteger JavaScript values; critical products and control sums use BigInt before checked conversion. Dart parsing and canonical license serialization reject values outside ±9,007,199,254,740,991 using explicit bounds, including the native signed-minimum overflow case. Per-entry and directory-baseline limits remain bounded. Half-up rounding uses quotient/remainder rather than an unsafe `product + 500` intermediate. No floating-point accounting or lossy financial JSON transport was added.

Source/restore controls refuse aggregates beyond the safe serialized range and block export/cleanup. This is a refusal contract, not support for arbitrary-size customer balances. A whole-program proof of every long-lived report sum has not been established. The authenticated annual manifest contains plaintext private account identifiers and financial controls; encrypted chunks do not conceal those values. It requires the same restricted access as the financial records.

## Active recovery and immutable local evidence

Schema 4 adds durable snapshot headers/pages and accepted review facts. The authenticated gateway supplies the expected canonical header SHA-256 and the verified membership epoch; the header binds tenant, UID, role, epoch, checkpoint, floor, counts and content digest. Pages can arrive in any order and survive reopening. Every page hash, global ordering/identity uniqueness, count and final descriptor digest must verify before installation. Active readers and the cursor remain unchanged while staging.

A fresh authenticated bootstrap increments the epoch. A newly bound snapshot ID may reuse staged pages only for identical tenant/UID/role, checkpoint/floor, counts and content digest, after revalidation. This preserves progress across the controller's maximum **16 newly downloaded pages per synchronization**. A late response after sign-out, a wrong scope/epoch, altered publication or bad page fails without installing into either account.

Installation merges accepted full-history facts, cursor C and history floor in **one transaction**. Outbox IDs/payloads, retry attempts/deadlines, drafts, conflicts and provisional review state are retained; snapshot presence never acknowledges a queued operation. Immutable payload collisions, conflicting review IDs, or a server entry that disagrees with the full provisional approval entry abort installation and cursor advancement. Newly captured accepted review bytes are durable immutable evidence; schema-3 records and existing user backups cannot retroactively prove review payload bytes they never retained. Fresh authenticated feed/snapshot data establishes that evidence going forward.

The wire/staging envelope is bounded to 4,096 pages, 500,000 records, 64 KiB canonical record arrays per page, 24,000 bytes per record and 256 MiB of serialized staged record arrays (a format limit, not a physical disk-use promise). Installation has a stricter **combined 20,000-record / 16 MiB serialized budget** across existing retained projections/review evidence, pending approval payloads and incoming records, because current validators load in-memory projections. A larger otherwise valid staged snapshot returns `snapshot_install_budget`; the existing ledger, cursor, staged progress and local operations remain intact. This is an explicit supported-envelope limit, not unbounded recovery acceptance.

## Archived statements, reports and provenance

Manager-only archived party statements now have a backend route, continuation pinned to the original manifest hash, client assembly, read-only UI, and CSV/Arabic PDF exports. Each page is bounded to **1 MiB / 2,048 rows**; completed client assembly is bounded to **20,000 records / 16 MiB**. A statement beyond these limits, with missing relevant originals, invalid arithmetic, changed publication or incomplete pages fails before exposing/exporting an invented complete statement. The client independently checks exact opening/period/closing arithmetic and reference/reversal effects; it relies on the authenticated gateway for archive decryption and manifest authentication. This is bounded annual party access, not an indexed unrestricted cross-year search service.

Original party opening values in reference snapshots are explanatory; the annual opening baseline is authoritative for that statement and is counted once. Current-period rows affect the running balance; references are not reposted. Merchant/supplier accounts and signed advances remain separate. CSV tests cover canonical negative amounts, formula-prefix escaping, quotes and multiline notes. PDF tests cover parser-derived role balances, correction evidence and long Arabic/multipage output.

Recorded net cash remains recorded inflows minus outflows, not reconciled physical cash on hand. No inventory, custody, accrual, cashbox-opening or actual-profit model was added. Closed-period held entries/terms remain excluded from displayed accepted accounting while original queue/evidence is retained. Linked correction provenance survives replay/backup in separate local columns and is exported as original business date plus current posting date; it does not authorize another posting.
