# مراجعة تجهيز الخادم المجاني — ٢٠ أكتوبر ٢٠٢٦

المشروع موجود محلياً واستُكمل فحصه من الحساب الجديد. إعداد الخادم قابل للبناء، لكن لم يُنشر بعد، ولا يوجد APK جديد متصل بالخادم البديل. المطلوب الآن حساب Cloudflare مجاني باسم المالك وتأكيد البريد. لا تحتاج هذه الخطوة إلى شراء دومين أو إضافة بطاقة.

## ما نُفذ في الاستكمال

- إعادة تحليل Flutter: لا مشاكل، ونجاح ١١٥ اختباراً للتطبيق.
- نجاح ٣١ اختباراً للخادم، و١٤ لإعداد اتصال Firebase، و٤ لإعداد Worker.
- بناء Worker تجريبياً دون نشر: 8,574.23 KiB قبل الضغط و1,188.57 KiB gzip. لم تُغيَّر إصدارات الاعتمادات أو طبقة التوافق.
- قراءة إعداد قاعدة Firebase وفهارسها وقواعدها المنشورة؛ لم تُقرأ سجلات مالية ولم تُعدَّل بيانات أو قواعد أو صلاحيات.
- تجهيز أداة محلية منفصلة لخطة تسجيل أول مدير وتليفونه. الأداة لا تتصل بالشبكة ولا تنشئ حساباً أو منشأة؛ التنفيذ الفعلي ما زال إجراءً مستقلاً يحتاج مراجعة.

الأعداد تخص مجموعات الاختبار المسماة، ولا تُجمع مع الأعداد التاريخية المتداخلة. اختبارات Worker المحلية وAndroid السابقة تبقى أدلة تاريخية؛ لم يُعَد اختبار هاتف أو خادم منشور في هذه الجلسة. لا يوجد هاتف Android متصل حالياً. المخرجات الكاملة لفحوص Flutter الجديدة لم تُحفظ؛ حُفظ ملخص النتيجة ورمز الخروج دون إعادة تشغيلها لمجرد توليد سجل.

## شكل النشر المقترح للمراجعة

| المورد | المقترح والحالة |
|---|---|
| الاستضافة | Cloudflare Workers Free؛ الحساب ونطاقه لم يُحددا بعد. |
| اسم Worker | `strawberry-tenant-gateway`، اسم مقترح قبل الموافقة؛ الإعداد الحالي للمراجعة فقط. |
| المعالجة | فئة SQLite Durable Object واحدة `TradingGateway`، باسم ثابت `gateway-v1`. |
| عنوان HTTPS | يُحدد من حساب Cloudflare بعد ربطه. لا يوجد عنوان إنتاج معتمد الآن. |
| Android | `com.strawberrytrade.strawberry_trade`؛ تطبيق Firebase `1:713439663809:android:c0565e7ada543b0e2b6640`. |
| بيانات التشغيل | حساب خدمة Google مخصص؛ لم يُنشأ ولم يُصدر له مفتاح. مفاتيح APK والترخيص الحالية تُحفظ دون إعادة توليد. |
| أسرار Cloudflare | `FIREBASE_SERVICE_ACCOUNT_JSON` و`LICENSE_PRIVATE_KEY_PEM` و`LICENSE_PUBLIC_KEY_PEM`، بعد مراجعة الحساب والصلاحيات وتطابق المفتاح العام. |

مرشح صلاحيات الخادم هو: `datastore.databases.get` و`datastore.entities.get` و`datastore.entities.list` و`datastore.entities.create` و`datastore.entities.update` و`firebaseauth.users.get` و`firebaseauth.users.update`. يلزم اختبار الحساب المخصص فعلياً قبل الاعتماد؛ لا يُمنح Owner أو Editor أو صلاحيات إدارة IAM أو الفهارس. [صلاحيات Firestore](https://firebase.google.com/docs/firestore/security/iam)، [صلاحيات الحسابات](https://docs.cloud.google.com/identity-platform/docs/access-control).

حساب الخدمة يتجاوز قواعد Firestore، وصلاحيته على القاعدة المشتركة قد تصل أيضاً لبيانات الموقع القديم إذا اختُرق؛ ليست صلاحية معزولة على مسار منشأة واحدة. كذلك `firebaseauth.users.update` أوسع من إلغاء الجلسات فقط، ويؤثر في نطاق مشروع الحسابات. يجب توضيح ذلك ضمن الموافقة على إنشاء الحساب والمفتاح ورفعهما للاستضافة.

## الحدود والخطوات التالية

Cloudflare يعلن البدء دون بطاقة. الخطة المجانية محدودة: ١٠٠ ألف طلب Worker يومياً، وحصة منفصلة للوحدة تشمل ١٠٠ ألف طلب و١٣ ألف GB-s يومياً. Firebase المجاني يشارك الموقع القديم في حصص قاعدة البيانات، ومنها ٥٠ ألف قراءة و٢٠ ألف كتابة يومياً و1 GiB تخزين. نفاد الحصة قد يوقف المزامنة مؤقتاً؛ السجل المحلي وقائمة الإرسال يظلان محفوظين. لا تُفعَّل خطة مدفوعة تلقائياً. [Workers](https://www.cloudflare.com/products/workers/)، [حصص الوحدات](https://developers.cloudflare.com/durable-objects/platform/pricing/)، [حصص Firestore](https://firebase.google.com/docs/firestore/quotas).

أداء بدء Worker وحدود CPU على حساب مجاني فعلي لم تُقَس بعد. إعداد App Check يسمح بالتوزيع خارج Play ويتطلب سلامة الجهاز؛ نجاح الرمز على هاتف فعلي ما زال مطلوباً. لم يتبين شرط دفع حساب Play للمسار الحالي. [إعداد Play Integrity](https://developer.android.com/google/play/integrity/setup)، [عقد إعداد App Check](https://firebase.google.com/docs/reference/appcheck/rest/v1/projects.apps.playIntegrityConfig).

1. ينشئ المالك حساب [Cloudflare](https://dash.cloudflare.com/sign-up/workers) بالخطة Free ويؤكد البريد، أو يسجل الدخول إلى حسابه الحالي. لا يرسل كلمة المرور في المحادثة.
2. بعد معرفة الحساب، تُستكمل مراجعة العنوان ونسخة المصدر والصلاحيات والأسرار والفهرس وخطة التراجع. ما زالت الموافقات السابقة تشترط عرض الإجراء المحدد قبل إنشاء حساب خدمة أو رفع أسرار أو نشر خدمة.
3. بعد الموافقة فقط: تجهيز صلاحيات التشغيل والفهرس ثم النشر؛ اختبار رفض الرموز غير الصحيحة وApp Check على هاتف، وبعده تسجيل مدير موثوق دون إعادة تشغيل تجربة منشأة قديمة.
4. بناء APK جديد برقم إصدار أعلى وعنوان الخادم الصحيح وبنفس مفتاح التوقيع. اختباره على الموبايل، بما يشمل المزامنة وإعادة الإرسال والعمل دون إنترنت وPDF والتحديث دون فقد بيانات.

التراجع يكون بإيقاف العنوان الجديد أو الرجوع لنسخة Worker سابقة، مع حفظ سجلات Firestore وإيصالات العمليات وقائمة الإرسال. حذف التطبيق أو بياناته أو سجلات العمل ليس إجراء تراجع.
