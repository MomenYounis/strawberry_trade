# Executed isolated Android storage and signed v11 update acceptance

Executed on 2 November 2026, using synthetic data in a separate API35/google_apis/x86_64 AVD. These are storage acceptance results, not production or commercial readiness approval. The owner’s existing `strawberry_test_api35` AVD, physical devices, real accounts and production data were untouched. No production authentication, device enrollment, business operation or cloud write was attempted.

## Runtime and exact scope

`runtime.json` identifies the unique private AVD path and the full process command. `boot-ready.json` records initial isolation; `boot-ready-restarted.json` records the same private AVD/data after its renderer restart. The runtime uses `emulator-5580`, a private `/tmp/strawberry-annual-native-20261102-da3kvv_i/avd` directory, host graphics with Vulkan disabled, 1 GiB guest RAM and two cores. Airplane mode was enabled and Wi-Fi/mobile data disabled before application operations and rechecked after reboot. An unreachable emulator HTTP proxy and loopback DNS were also configured at launch.

There are **three unique native persistence assertions**, repeated in the roundtrip, seed, verification and reboot phases. Do not add repeated phases or framework teardown counters as new test coverage:

1. Actual Android Keystore P-256 installation identity/challenge proof and protected key/value scope isolation.
2. Actual SQLCipher4 encrypted entry/outbox commit and reopen, wrong-key rejection, preserved installation identity and protected database key, stable queued operation/payload digest, retry count/time and unfinished draft.
3. Representative encrypted schema1→4 migration preserving pending payload, retries and draft.

The fixture hash is `d422c631acdec4d0f0f66a17e1e73a725328c66c943d62eab3b275176d01347a`. Explicit SQLCipher errors for the intentionally incorrect database password are expected evidence of wrong-key rejection, not a successful plaintext fallback.

## Reproduction and remaining limits

`tools/annual-review/native-storage-check.py persistence` runs the guarded initial roundtrip. `tools/annual-review/native-v11-upgrade-check.py` separates `seed`, `replace`, `verify` and `reboot-verify` phases, requiring the matching private process/path, offline device, signatures, versions, fixture hash and preceding results. After seeding it uses only explicit retaining-data `adb install -r` and attaches a plain host Dart integration driver to the already running app. This avoids Flutter’s installer fallback, which can uninstall an existing package after an install failure. Local VM-service authorization values are held in memory and redacted from evidence logs; signing credentials remain in anonymous memory files through the existing helper.

Not tested by this campaign: normal manager/employee account or license recovery, native multi-device business synchronization, invitation/device-transfer flows, archive storage access, native active-snapshot stage/install recovery, replacement-phone/archive-plus-active-data disaster recovery, production quotas/deployment compatibility, physical OEM/older-Android behavior, sharing/printing/accessibility, or annual-volume native performance. The previous isolated `SQLITE_FULL` test from 1 November remains separate baseline evidence and was not rerun or recounted here. These results do not remove the four production/commercial NO-GO verdicts.

After root visually inspected the settled v11 setup screenshot, `runtime-cleanup.json` recorded successful cleanup. The exact private PID32353, full AVD path/name, owner UID and temporary-directory prefix were rechecked, all four signed campaign phases were confirmed PASS, and only `emulator-5580` was stopped. The owner’s AVD and devices were untouched; no owner AVD was deleted.
