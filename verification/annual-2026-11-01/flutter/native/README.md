# Executed disposable Android storage acceptance

These are synthetic API35/x86_64 Android results, not production acceptance or replacement-phone disaster recovery. The owner's devices, existing `strawberry_test_api35` AVD and real accounts were untouched. A new private AVD named `strawberry_annual_disposable` used `emulator-5580`. Airplane mode was enabled, Wi-Fi and mobile data disabled before fixture or release-APK launches. No Firebase gateway fixture ran in this campaign.

## Passed scope

- `local-persistence.log`: three native tests passed, exit0. Actual Android Keystore P-256 proof, scoped protected keys, SQLCipher4 encryption/wrong-key rejection, ledger/outbox reopen and representative encrypted v1→v3 migration. The first renderer disappeared after assertions; Flutter reported a force-stop timeout during cleanup. Do not treat that runtime warning as a reliable emulator session.
- `full-storage-roundtrip.json` / `.log`: guarded rerun PASS, exit0. A real isolated SQLCipher pager reached `SQLITE_FULL` code13 at128×4096bytes. The financial transaction surfaced the exact known secondary rollback error; no partial ledger/outbox/audit effect remained, the draft survived reopen, and same-ID retry succeeded once. This limited one database, not the host filesystem.
- `signed-seed-drive.json` / `.log`: PASS. A DEBUG persistence fixture, version8, was signed locally with the existing certificate and seeded an encrypted entry, stable queued payload, retry schedule and draft. The fixture deliberately removed only schema3 additions and set schema2, asserting that version before stopping. These are representative legacy bytes, not an export of a real customer's old app.
- `signed-apk-replacements.json`: the actual existing signed v9 APK and final signed v10 review APK were installed with `adb install -r` over that seed, both exit0. The final release APK cold-started offline to its Arabic setup screen (`signed-v10-offline-start.png`). No account login or financial operation was attempted there.
- `signed-verify-drive.json` / `.log`: PASS after those replacements. A separately signed DEBUG verify fixture (same package/certificate, version10) reopened the retained data, migrated schema2→3, and checked the installation identity, SQLCipher key digest, encrypted entry, stable outbox operation/payload digest, retry count/time and unfinished draft. No uninstall/data-clear occurred after the persistent seed.
- `signed-reboot-verify.json` / `.log`: PASS after reboot of the same disposable Android. Airplane mode stayed enabled and Wi-Fi/mobile data stayed disabled; the same protected key and queued evidence survived reopening. This is storage recovery, not a normal cached-account/license or archive+active-data recovery test.

Native phases repeat three named persistence tests; do not add framework counters or repeated runs as unique coverage. The DEBUG seed/verify APKs are test instruments and must never be distributed as release artifacts. The final release artifact is identified independently by `../release-build-final.json` and `../apk-inspection-final.json`.

## Reproduction and limits

The runtime must first be provisioned as a new private disposable AVD from the installed `system-images;android-35;google_apis;x86_64` image. `runtime.json` identifies the owned private path/process; never substitute the owner's AVD or a physical serial. `tools/annual-review/native-storage-check.py` refuses a missing/wrong synthetic runtime and verifies offline isolation before running storage-only fixtures. `tools/annual-review/sign-native-fixture.py` accepts only the debug persistence entrypoint/package and explicit version8/10; it uses existing signing credentials via an anonymous memory file, with no password argument or disk file. The native driver uses `--keep-app-running` to preserve app data. No production signing identity was created or replaced.

One initial removal of the disposable debug app happened **before** the persistent seed to switch from its default debug certificate to the existing release certificate (`pre-seed-disposable-reset.json`). No owner app was removed. No uninstall or data clear happened during the signed update/reboot sequence.

Intermediate environment/tooling failures remain visible: the software renderer failed to become usable (`full-storage.log`); the supervised host renderer with Vulkan disabled then ran successfully. An initial signing helper supplied only one password-file line while apksigner consumed separate store/key lines; the helper was repaired and both final fixture signatures verify. No key/password was changed. These failed preparations are not counted as passed application tests.

Still NOT RUN here: native manager/employee multi-device financial sync against the compatible gateway, invitation/license/account recovery under real deployment settings, replacement-phone recovery, physical handset/OEM and older-Android coverage, native archive storage access, accessibility/share/print acceptance, and long-running native annual-volume performance. Full-system snapshot installation and post-pruning recovery remain NOT IMPLEMENTED. The four commercial/production verdicts stay NO-GO; see `docs/commercial-release-readiness.md`.
